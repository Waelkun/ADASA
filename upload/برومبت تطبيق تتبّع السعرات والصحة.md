```
ROLE
You are a senior full-stack engineer and product designer. Build a production-ready, mobile-first web app (installable PWA) called "Nutra" for personal nutrition and fitness tracking. Single user per account. UI language: Arabic (RTL) with an English toggle. Numbers use Western digits.

STACK
- Next.js 15 (App Router) + TypeScript + Tailwind CSS + shadcn/ui + Recharts
- Supabase: Postgres, Auth (email magic link + Google), Storage (private bucket "meal-photos"), Row Level Security on every table (user_id = auth.uid())
- Deploy on Vercel. Use env vars: NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY, ANTHROPIC_API_KEY
- AI calls happen only in Next.js Route Handlers (server side), never in the browser
- Provide: SQL migration file, .env.example, README with setup + deploy steps
```

## ٣. مسح المنتج بالصورة (الميزة الأساسية)

```
FEATURE 1: PHOTO SCAN OF PRODUCT + NUTRITION LABEL
Flow:
1. "+" > "Scan product". Open camera via <input type="file" accept="image/*" capture="environment"> (and gallery option). Allow up to 2 photos: (a) the front of the product, (b) the nutrition facts label on the back. Back photo is the primary source of truth; front photo is used for the product name/brand.
2. Compress images client-side (max 1600px, JPEG 0.8) and upload to Supabase Storage.
3. POST /api/scan sends both images to Claude (vision) with a strict system prompt: read the nutrition label, return ONLY valid JSON:
{ "product_name": string, "brand": string|null, "serving_size_g": number|null, "servings_per_container": number|null,
  "per_100g": { "kcal": number, "protein_g": number, "carbs_g": number, "sugar_g": number|null, "fat_g": number, "sat_fat_g": number|null, "fiber_g": number|null, "salt_g": number|null },
  "per_serving": { same fields } | null,
  "confidence": 0-1, "notes": string }
   Rules in prompt: never guess values that are not visible, use null; support Arabic and English labels; convert kJ to kcal if needed; detect per-100g vs per-serving columns.
4. Validate JSON with Zod. Sanity check: kcal ≈ 4*protein + 4*carbs + 9*fat (±20%); if it fails, flag "Please verify values".
5. Show a result sheet with editable fields, a quantity input (grams OR servings, with quick chips 50g / 100g / 1 serving), live-calculated totals, meal selector (Breakfast / Lunch / Dinner / Snack), then "Add to log".
6. Save the product in a personal "My foods" table so the next scan of the same product (match by name + brand) is instant. Add search + favorites for My foods.
7. Fallback: manual entry form and barcode-less quick add (name + kcal + macros).
8. Handle errors clearly: blurry photo, label not found, network failure, with a retry button.
```

## ٧. قاعدة البيانات والأمان

```
DATABASE (Supabase, all tables have user_id uuid references auth.users, created_at, RLS policies for select/insert/update/delete)
- profiles(user_id pk, display_name, sex, birth_year, height_cm, activity_level, goal_type, kcal_goal, protein_g, carbs_g, fat_g, water_goal_ml, goal_weight_kg, workouts_per_week, units, locale)
- foods(id, name, brand, serving_size_g, kcal_100g, protein_100g, carbs_100g, sugar_100g, fat_100g, sat_fat_100g, fiber_100g, salt_100g, image_path, is_favorite)
- food_logs(id, food_id nullable, name, logged_at, meal_type, grams, kcal, protein_g, carbs_g, fat_g, source: 'scan'|'manual')
- weight_logs(id, date, weight_kg, note, unique(user_id, date))
- water_logs(id, logged_at, amount_ml)
- workouts(id, date, muscle_groups text[], duration_min, note)

SECURITY & QUALITY
- Rate-limit /api/scan (e.g. 20/hour/user), reject files over 8 MB or non-images
- Store only the path in the DB; serve images via signed URLs
- Index (user_id, date) on all log tables; use server components for data fetching where possible
- Optimistic UI for quick adds; loading skeletons; empty states with a clear action
- PWA manifest + icons, 44px minimum touch targets, WCAG AA contrast

DELIVERABLES
Full project code, SQL migration, seed script, README with: Supabase setup, env vars, Vercel deploy steps. Build in this order: auth + schema + layout, then scan flow, then log/today, then weight, water, workouts, then polish.
```
